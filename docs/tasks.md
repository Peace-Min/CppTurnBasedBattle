# 작업지시서

작업은 순서대로 진행한다. 각 단계가 끝나면 완료조건을 확인한다.

## T01. 솔루션 뼈대 만들기

### 할 일

- `BattleCore` 정적 라이브러리 프로젝트를 만든다.
- `BattleApp` 콘솔 프로젝트를 만든다.
- `BattleTests` GoogleTest 프로젝트를 만든다.
- `BattleApp`과 `BattleTests`가 `BattleCore`를 참조하게 한다.

### 완료조건

- 세 프로젝트가 Debug x64로 빌드된다.
- 빈 GoogleTest 하나가 Test Explorer에서 실행된다.

## T02. `Weapon` 구현

### 할 일

- `Weapon.h`, `Weapon.cpp`를 만든다.
- 이름과 공격력을 저장한다.
- getter를 `const` 멤버 함수로 만든다.

### 테스트

- 이름이 입력값과 같다.
- 공격력이 입력값과 같다.

### 완료조건

- 테스트 2개 이상 통과.
- 헤더에 `using namespace std;`가 없다.

## T03. 플레이어 공통 상태 구현

### 할 일

- `Player`에 이름과 체력을 추가한다.
- 체력이 음수가 되지 않도록 한다.
- `is_alive()`를 구현한다.

### 테스트

- 초기 체력이 올바르다.
- 피해를 받은 뒤 체력이 감소한다.
- 큰 피해를 받아도 체력이 0 아래로 내려가지 않는다.
- 체력 0에서 사망 상태가 된다.

## T04. 공격과 다형성 구현

### 할 일

- `IPlayer`에 공격 인터페이스를 정의한다.
- `Archer`와 `Warrior`를 구현한다.
- 모든 상속은 `public`으로 명시한다.
- 기본 클래스 소멸자는 `virtual`이어야 한다.

### 테스트

- `IPlayer&`로 궁수와 전사를 각각 공격시킬 수 있다.
- 공격 후 대상 체력이 감소한다.

## T05. `Battle` 구현

### 할 일

- `Battle`이 플레이어 두 명을 소유하게 한다.
- 소유권은 `std::unique_ptr`로 표현한다.
- 턴 순서대로 공격시킨다.
- 사망자가 나오면 전투를 종료한다.

### 테스트

- 두 플레이어가 등록된다.
- 한 턴에 한 번만 공격한다.
- 승자가 올바르게 결정된다.
- 전투가 끝난 뒤 추가 공격이 실행되지 않는다.

## T06. 콘솔 앱 연결

### 할 일

- `BattleApp`에서 궁수와 전사를 생성한다.
- `Battle`을 실행한다.
- 턴 로그와 최종 승자를 출력한다.

### 완료조건

- 앱을 실행하면 처음부터 끝까지 한 번의 전투가 진행된다.
- 테스트 프로젝트에 앱 전용 코드가 들어가지 않는다.

## T07. 정리와 회고

### 할 일

- 중복 코드를 제거한다.
- 불필요한 raw pointer를 제거한다.
- 클래스별 헤더와 소스 파일을 확인한다.
- 테스트 이름을 동작 중심으로 정리한다.

### 완료조건

- 모든 테스트 통과.
- Debug 빌드와 Release 빌드 통과.
- 각 클래스의 소유권을 한 문장으로 설명할 수 있다.
